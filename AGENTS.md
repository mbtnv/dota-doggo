# Работа над dota-doggo

- Полезная функциональность и сохранность данных важнее устройства Python-проекта.
  Используйте идиоматичный Go; улучшения пользовательского поведения документируйте.
- Источник сценариев: `docs/functional-contract.md` и `testdata/`. Реализация
  Python находится в соседнем `../dota-dog`; не изменяйте её при переносе.
- Go toolchain закреплена в `.go-version` и `go.mod`.
- Перед сдачей изменений: `make check` и `make build`.
- Изменения SQL и репозиториев проверять на отдельной PostgreSQL через
  `TEST_DATABASE_URL=... make test-integration`. Не использовать production-БД.
- Изменения миграций проверять для пустой базы и принятия legacy-схемы;
  проверять отказ на несовместимой схеме и повторный запуск.
- Тесты пользовательских сценариев добавлять вместе с реализацией.
- Не коммитить секреты, локальные env-файлы, бинарники и дампы реальных баз.
- Не заявлять готовность этапа, пока соответствующие проверки не выполнены.
